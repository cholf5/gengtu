下面评估"让 8 个手柄贴在斜框角上"的代价。

现状回顾

TextBoxOverlay 现在的结构：

<Rnd>                       ← 轴对齐 AABB；持有 position/size/handles/拖拽/缩放
<div .text-box-frame>     ← 旋转的视觉边框（dashed border / selection ring）
	{children}
</div>
</Rnd>

数据模型里 (x, y, width, height) 始终描述未旋转的、轴对齐的矩形，旋转只是渲染时绕中心转。fromPreviewRect /
clampBoxToImage / Canvas 的 translate→rotate→draw 全部依赖这个不变量。

三条修复路径，按代价从小到大

路径 A：保持 AABB 数据模型，让"看上去像 8 个手柄贴在斜框上"——视觉骗术

把 react-rnd 自带的 8 个手柄（外层 AABB 角上）隐藏（enableResizing: false 或纯 CSS display: none）；在 .text-box-frame
里手画 8 个 div 当作手柄，挂自己的 pointer 事件，把拖拽 delta 投影回未旋转坐标系（一个 cos/sin 矩阵旋转），再
setState 更新 width / height / x / y。

代价：
- 一个新文件 RotatedResizeHandles.tsx（约 120–180 行）：8 个 corner/edge 的 pointer 事件、delta 反旋转、最小尺寸
clamp。
- TextBoxOverlay 把 react-rnd 的 resizing 关掉，只保留 drag。
- Canvas / 几何不动，测试不动，没有数据迁移。
- 风险：会把"沿斜框法线方向 resize"的细节做对，需要 1 次以上手感调试。bounds 限制要自己写（react-rnd 的
bounds="parent" 不会管手画的 handle）。

我的估计：1.5–3 小时，低风险，可逆（任何时候删掉手画 handle 就回到现在的状态）。

路径 B：换掉 react-rnd，用 react-moveable 或 interactjs

它们原生支持旋转 + 旋转感知 resize。功能更全（还能给"旋转手柄"），但是：

代价：
- 重写 TextBoxOverlay：position/size/rotation 都走库的回调。
- 多一个依赖（react-moveable 压缩后约 30KB gzip；interactjs 约 25KB）。
- 库的 onResize 给的是新的 width/height + translate，要把 translate 折算回 x,
y（中心位移）；如果旋转和缩放同时进行，还要处理"中心是否漂移"的语义。
- 几何/canvas 数据模型可以保持不变，但预览侧的 mental model 要重做一遍。

估计：4–6 小时，中风险。换库收益不止"贴角的手柄"——还会附送旋转手柄（鼠标拽就转），可能比滑块更顺手。

路径 C：把数据模型从 AABB 升级为"中心 + 宽高 + 旋转"

这是"最对"的方案。但代价远超前两条：buildTemplateJson / clampBoxToImage / fromPreviewRect / Canvas / 现有所有模板 JSON
全要迁移。除非以后真要做"沿任意角度对齐多个 box"之类的事，不建议现在做。

建议

走 路径 A。它把范围切得很窄（一个新组件 + 一处接线），数据模型不动，测试不动，未来想升级到 react-moveable
也没有沉没成本。除非你已经看上 react-moveable 的旋转手柄手势——那就直接 B。

你倾向哪条？如果选 A，我直接动手；如果选 B，我先看一眼 react-moveable 的 API 再开工。
